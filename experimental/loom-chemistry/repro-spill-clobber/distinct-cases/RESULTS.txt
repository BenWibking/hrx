CONFIRMED REPRODUCER: break-170.loom
---------------------------------
The loop has a uniform maximum of four iterations. A separate branch in its
body exits directly to the loop continuation when k >= bound. Runtime mode
sets bound to 4-lane (divergent) or 4 (uniform). Thus it explicitly tests a
body break rather than using the per-lane bound as the header condition.
The body still contains the divergent arithmetic branch from the existing
loop reproducer. This is a loop-retirement reproducer, not proof of a new
independent root cause.

Three native runs reproduce EXPECT/001 at element 256 (lane 1, value 86),
residual -5: actual 3 instead of expected 8. Uniform-trip control passes.
Width 192 likewise fails with a passing uniform control.

NEGATIVE RESULTS: no demonstrated runtime bug
---------------------------------------------
branch-144.loom has no loop: lanes 0/1 double the input state and lanes 2/3
quadruple it, then merge. Mode 0 selects the same branch for all lanes.
Passing widths: 96,112,124,128,144. Widths 170 and 192 are rejected during
allocation (spill-traffic-register-exhausted), not runtime counter clobbers.

nested_branch-112.loom adds an outer diamond: lanes 0/1 double, lane 2
quadruples, lane 3 multiplies by eight. Widths 80,96,112 pass; 128 hits an

masked_update-170.loom tests if(predicate) state=updated; otherwise state is
preserved through explicit SSA incoming values. Width 170 passes with 170
spill diagnostics; widths 176,184,192 hit allocation rejection.

unrolled-170.loom applies four successive predicated updates. The active
set shrinks after each stage, but there is no loop backedge. State doubles
only in active lanes and explicit false-path values retain prior state.
Widths 128,144,170 pass. Width 170 has 432 spill diagnostics. This is the
strongest tested non-loop inactive-lane preservation control.

select-252.loom uses scf.select for every update. Widths 170,192,248,252 pass;
256 and 320 hit allocation rejection. The successfully compiled 252-value
case does not spill, so it is not evidence for spilled select results.

Second investigation: distinct values and retained histories
----------------------------------------------------------
Same clean upstream compiler and MI300X. generate_distinct_values.py uses
state[j]=j+1 from runtime input, four successive regions, and cross-cutting
predicates. Lanes leave and later re-enter the active set. True paths add
neighboring elements; alternate branch paths subtract a different neighbor.
Python computes each expected integer independently before generating IR.

Results (mixed-lane and uniform controls both pass when compilation succeeds):
- Branches: widths 96 and 144 pass; width 170 hits allocation rejection.
- Predicated updates: 96 and 144 pass; 170 hits allocation rejection.
- Pure selects: 96,144,170 pass (170 has zero inserted spill diagnostics).
- Confirmed spill counts: branch-144 304; update-144 175.

Then generate_live_history.py retains EVERY intermediate state version until
all four regions finish and checks every version, forcing values to stay
live across later masked regions. This avoids tests accidentally passing
because identical values hide a wrong-register read, and forces spills even
for the select case.

SOURCE AUDIT
------------
The audited control.c and spill_lowering.c match upstream commit
bfff52cfd59049518a32576c8bd5dcef98b651be exactly (git diff is empty).

loom/src/loom/target/arch/amdgpu/lower/control.c:
- emit_masked_merge_restore_block (line 1558) restores saved EXEC and selects
  between explicit prior/false and updated/true values before forwarding.
- emit_if_else_merge_restore_block (line 1615) likewise restores EXEC and
  combines separately represented true and false payloads.
- emit_masked_merge_value (line 1498) emits the per-value merges; native i1
  masks have their own explicit Boolean merge.
- emit_no_true_else_entry_block (line 1670) restores parent EXEC before
  defining placeholders for a skipped arm. Those placeholders are ignored
  by the eventual select.
- emit_divergent_loop_blocks (line 1795) saves parent EXEC and wires the
  restore block. Its exit restore uses emit_exec_restore_block (line 1218),
  which restores EXEC and forwards arguments but does not merge retired
  lanes' earlier-iteration values with current-iteration values.

The relevant distinction is dynamic re-execution, not simply a partial
mask. In an acyclic lowered region, a branch-arm value only has to be valid
in the lanes selecting that arm. At reconvergence an explicit select picks
the right arm for each lane. Undefined inactive components may be snapshotted
by a full-EXEC spill, but those components are not selected as the result.
Live values from other arms are separate SSA inputs with explicit liveness.
This reasoning composes for nested and sequential accepted branch regions.

A loop executes the SAME static definitions and spill stores again with a
shrinking mask. A retired lane needs an earlier dynamic instance of a value,
while active lanes produce newer instances. Later full-EXEC stores can
replace that earlier lane value. The loop exit widens EXEC without an
explicit SSA preservation merge for the retired lanes. The dynamic instances
have been collapsed into one static spill slot without the necessary
lane-wise recurrence.

CONCLUSION AND SCOPE
--------------------
I am convinced this specific retired-lane/earlier-iteration spill clobber is
loop-specific in Loom's currently supported high-level AMDGPU control-flow
lowering. This conclusion combines a structural argument with the positive
loop/break reproducers and the stronger negative acyclic tests. It is not a
formal proof that every non-loop allocation is correct or that no unrelated
masking bug exists. The divergent early-return shape is rejected and is
outside the set of successfully lowered programs checked here.

This also corrects the earlier broad statement: a partial execution mask
alone is insufficient to explain this bug. The problematic missing dataflow
is retention across loop iterations. It can affect branch-result temporaries
inside the loop as well as values explicitly named as loop-carried in source.

The older explicit-low diagnostic manually substitutes a whole-register
spill for a masked assignment. Its loop-free form is not a counterexample:
it demonstrates that invalid substitution, not an automatic transformation
of a valid acyclic high-level program.
